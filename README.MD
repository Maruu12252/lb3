## Аналіз початкового коду (Знайдені помилки)

1. **Відсутність обмеження розміру черги (Витік пам'яті):**
   Початковий клас `SharedQueue` використовував `deque()` без обмеження розміру. Якщо потік-виробник працює швидше за споживачів, черга зростає безконтрольно, що з часом призводить до `MemoryError`.
2. **Втрата даних при кількох виробниках (Глобальний прапорець):**
   Змінна `self._is_producing` була спільною для всієї черги. Якщо додати другого виробника, перший, хто завершить роботу, викликав `stop_producing()` і зупиняв споживачів. Дані від повільнішого виробника залишалися в черзі назавжди і не оброблялися.
3. **Мертвий код (Dead Code):**
   У методі `consume` після виходу з циклу `while not self._queue:` знаходилася перевірка `if not self._queue: return None`, яка ніколи не виконувалася через логіку `Condition.wait()`.

## Пояснення виправлень
* **Обмеження черги (Backpressure):** Додано параметр `max_size`. Замість одного `Condition` тепер використовується два: `_not_empty` та `_not_full`, прив'язані до одного `Lock`. Виробник блокується (`_not_full.wait()`), якщо черга переповнена.
* **Підтримка N-виробників:** Замість булевого прапорця `_is_producing` введено лічильник `_active_producers`. Споживачі зупиняються лише тоді, коли всі зареєстровані виробники завершили роботу (`_active_producers <= 0`).
* **Оптимізація коду:** Видалено мертвий код. Блокування стали більш точковими та зрозумілими.
